# BaseLinker: заказ без списания со склада

Задача: создать заказ, который
1. попадает в статус (папку) **`Online — opłacone / nowe`**,
2. отмечен как оплаченный,
3. **не списывает товар со склада**,
4. не печатает чеки/фактуры.

## Как это работает

Метод — [`addOrder`](https://api.baselinker.com/index.php?method=addOrder).
Отдельного флага «не списывать склад» в нём **нет**. Списание зависит от того,
привязана позиция заказа к каталогу или нет:

| Поле `product_id` в позиции | Что происходит со складом |
|---|---|
| указан реальный ID товара | остаток списывается **сразу** при создании заказа |
| пустая строка `""` | остаток **не меняется** |

То есть «не списывать» = отправить позицию как несвязанный текстовый товар:
имя, SKU, EAN, цена, количество — но `product_id: ""`.

```python
{
  "storage": "db",
  "storage_id": 0,
  "product_id": "",      # <-- ключевой момент
  "variant_id": 0,
  "name": "...", "sku": "...", "ean": "...",
  "price_brutto": 10.00, "tax_rate": 23, "quantity": 2
}
```

Остальное:

* `order_status_id` — ID статуса, берётся из `getOrderStatusList`.
  Для этого аккаунта `Online — opłacone / nowe` = **507215**.
* `paid: 1` — BaseLinker сам добавляет полную оплату, заказ становится оплаченным.
* `want_invoice: 0` — без фактуры. Чеки/фактуры `addOrder` сам не печатает
  вообще: печать в BaseLinker запускается вручную или автоматическими
  действиями (Menedżer akcji), привязанными к статусу.

## Проверка (реальный прогон на аккаунте)

Тестовый товар: `TEST-API-001`, `product_id = 675097701`, склад `bl_123819`, остаток 100.

| Шаг | Остаток |
|---|---|
| до тестов | 100 |
| заказ `48331786` — позиция **с** `product_id` | **98** — списалось |
| заказ `48331820` — позиция **без** `product_id` | **98** — не изменился |

Оба заказа ушли в статус `507215` и отмечены оплаченными на 20 PLN.
После проверки остаток возвращён на 100.
